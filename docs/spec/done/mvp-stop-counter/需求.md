# MVP 核心数站提醒

## 一、要解决的问题

坐地铁时不确定「还有几站到目的站」，怕坐过站。本需求交付 MVP：**一键开始 → 自动数站 → 目的站前一站 + 到站提醒 → 自动结束**。

稳定的跨期内容（背景 / 范围 / 技术选型 / 架构 / 状态机规格 / 参数初值 / 平台要点 / 数据格式）**不在本文件重复**，见 [`../../需求与方案.md`](../../需求与方案.md) 第三～七节。

## 二、本需求范围

| # | 交付物 | 说明 |
|---|---|---|
| 1 | 路线选择 UI | 线路 / 方向 / 上车站 / 目的站，目的站限选上车站之后；默认上次路线 |
| 2 | 一键开始 | QS 磁贴 / App 内按钮（桌面小组件在 M3 补） |
| 3 | 前台服务 + 传感器采集 | `specialUse` + `PARTIAL_WAKE_LOCK`，50 Hz |
| 4 | 状态机 v1 | 规格见总纲第五节（三条件联合判定 + 去重计数） |
| 5 | CSV 三件套 | 传感器 / 事件 / meta，供回放调参 |
| 6 | 调试面板 + 离线回放 | M1 验收必需 |
| 7 | 通知 | 常驻进度 + 目的站前一站提醒 + 到站确认 + 异常（渠道见总纲第六节） |
| 8 | 手动纠错 | 通知按钮「我已多过一站」+ App 内 ±1 |
| 9 | 自动结束 | 到站后延时结束；最长 90 分钟兜底 |
| 10 | 保活向导 | 红米 / HyperOS 五步 |

## 五、验收标准（M1 / S2）

1. `gradlew.bat assembleDebug` 一次通过、`adb install -r` 成功，连续运行 30 分钟无 crash；
2. 点磁贴 / 按钮 → 3 秒内出现常驻通知（后台启动也 ≤10 s 可见）；锁屏 10 分钟后 logcat 仍有稳定 50 Hz 数据；
3. **地铁实测 ≥5 站：识别站数误差 ≤1 站**；`sensor.csv` 离线回放的事件序列与现场完全一致；
4. `gradlew.bat test` 通过，含首个 `CsvReplayTest`（用首次实测 CSV 作为回归用例）。

## 六、已知限制（先接受，不阻塞验收）

- 跳站快车 / 区间车：传感器无法感知「未停车」→ 计数偏移，靠提醒文案带**站名** + 手动纠错；
- 手机拿在手里 / 外放音乐：抬高振动基线可能漏检，靠引导与阈值调整；
- 换乘线路不在本需求范围（见总纲第十一节）。
