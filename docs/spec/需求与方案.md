# 需求与方案（总纲）

> 本文件是**跨期总纲**，只写稳定的东西（背景 / 范围 / 技术选型 / 架构 / 里程碑总表 / 后续优化 / 风险）。
> - 开发中的详细需求：`active/mvp-stop-counter/需求.md`
> - 需求状态速览：`docs/README.md`
> - 目录与状态规则：`spec/README.md`

## 一、背景

- **需求由来**：OPPO 系统有「到达地铁站即在灵动岛提示到了哪一站」的能力（ColorOS 流体云，靠系统级 Wi-Fi + 基站融合与大数据判断，地下 GPS 不可用）；小米无此功能。用户希望自研一个**个人自用** App 解决「坐地铁怕坐过站」。
- **关键约束**：地铁隧道内 GPS 无信号 → **不依赖定位**，采用**加速度传感器识别列车进站（减速-停稳）并计数**的方案。
- **形态**：可侧载 APK，跑在红米 K80（HyperOS 4 beta / Android 17）；普通通知即可，**不做小米超级岛**（避开其焦点通知白名单审批）。

## 三、技术选型

| 项 | 选型 | 理由 |
|---|---|---|

## 四、架构设计

### 4.1 分层（单模块 `:app`）

- `core/`：**纯 Kotlin（禁 `android.*`）** —— 特征提取、状态机、路线模型、CSV 回放 → JVM 单测可直接跑；
- `platform/`：Android 壳 —— 前台服务、传感器采集、通知、DataStore、磁贴、小组件、唤醒锁、CSV 写盘；
- `ui/`：Compose 单屏。

### 4.2 数据流（状态来源单一：服务写、UI/磁贴/小组件读）

```
SensorCollector(50Hz) → FeatureExtractor(H 减速 / vib 振动) → StationStopDetector(状态机→事件)
  → MonitorSession(计数 / 提醒去重) → 通知 + SessionHolder(StateFlow) → UI / 磁贴 / 小组件
```

## 五、停站识别规格（核心算法）

### 5.1 特征

- `H` = 去重力后水平分量经 0.4 Hz 低通（1 s 均值）→ 列车纵向加减速（**刹车判据**）；
- `vib` = 3–20 Hz 带通 RMS（1 s 窗）→ 行驶 / 停稳判据；
- `stillFor / runFor / brakeFor` = 连续时长累计（按秒，不按样本数）。

### 5.2 状态机（`core/fsm/StationStopDetector.kt`）

状态：`IDLE → WARMUP → CRUISE ⇄ BRAKING → STOPPING → STOPPED（到站计数点）→ DEPARTING → CRUISE`；旁路 `INTERRUPTED`（断流）、`FINISHED`（自动结束）。

到站判定**三条件联合**：① 持续制动（H > 阈值 ≥ 3 s）；② vib 跌落（< 停稳阈值）；③ 静止累计 ≥ 8 s。

防误判与兜底：

- 两站最短间隔 60 s（低于则记 `STOP_SUSPECT` 不计数）；
- 起步前（`hasRun=false`）的第一个到站**不计数**（视为上车站本身）；
- BRAKING 超 30 s 或振动回升（曲线/缓行）→ `BRAKE_ABORT` 回 CRUISE；
- 断流 > 5 s → `INTERRUPTED` + 异常通知，恢复后重新预热 5 s；
- 开始后 20 s 内不判定（预热）；最长监测 90 分钟自动结束。

### 5.3 参数（唯一来源 `core/model/TuningConfig.kt`，实测后用 CSV 回放调整）

| 参数 | 初值 | 说明 |
|---|---|---|
| `vibRunTh` / `vibStopTh` | 0.25 / 0.08 m/s² | 「在动 / 停了」阈值（构成滞回） |
| `brakeAccelTh` | 0.40 m/s² | 制动判据（地铁常用制动约 0.8–1.3） |
| `brakeMinSec` / `brakeMaxSec` | 3 / 30 s | 制动持续合理范围 |
| `stillConfirmSec` | 8 s | 停稳确认（决定提醒延迟与抗扰动） |
| `departConfirmSec` | 5 s | 起步确认 |
| `minStopIntervalSec` | 60 s | 两站最短间隔 |
| `slowLpfHz` / `vibBand` | 0.4 Hz / 3–20 Hz | 滤波器参数 |
| `startGraceSec` / `maxMonitorMin` / `endGraceSec` / `dataGapSec` | 20 s / 90 min / 30 s / 5 s | 安全兜底 |

### 5.4 计数语义

- `k = index(D) − index(S)`（按该方向站序）；`n` = 已确认到站数；当前站 = `S + n`；下一站 = `S + n + 1`；剩余 = `k − n`；
- `n == k − 1` → 发「下一站：D，请准备下车」（高优先级 + 震动，**去重只发一次**）；
- `n == k` → 发「已到达：D」，`endGraceSec` 后自动结束；
- `n > k` → 发「您可能已坐过 D 站」（只发一次）；
- `k == 1` 特例：预热结束即发「下一站就是目的站」提醒。

### 5.5 边界与对策

| 情况 | 对策 |
|---|---|
| 起步加速 / 曲线横向加速 | 计数只发生在 STOPPED（需「振动跌落 + 静止 8 s」），天然免疫 |
| 中途信号停车 | 与到站无法从传感器区分 → 靠 60 s 间隔门槛 + 用户纠错；记录 dwell/interval 供离线分析 |
| 人在车厢走动 | 步态不产生「振动由高→极低并持续 8 s」的特征 |
| 手机拿在手里 / 外放音乐 | 抬高 `vib` 基线 → 漏检；App 内引导「放口袋」+ 实时 vib 显示自查 + 阈值可调 |
| 跳站快车 | 传感器无法感知「未停车」；提醒文案永远带**站名**兜底 + 手动纠错 |
| 手机任意朝向 | 算法基于重力投影，与朝向无关 |

## 六、Android 平台要点（结论）

- 前台服务类型 **`specialUse`**：`android:foregroundServiceType="specialUse"` + `<property android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE" android:value="乘坐地铁时识别列车到站并提醒"/>` + 权限 `FOREGROUND_SERVICE_SPECIAL_USE`；`onStartCommand` 首行 `startForeground`（5 秒红线）；常驻通知设 `FOREGROUND_SERVICE_IMMEDIATE`。应急开关：切 `health` 类型（编译期常量）。
- 权限：`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_SPECIAL_USE`、`POST_NOTIFICATIONS`（运行时）、`VIBRATE`、`WAKE_LOCK`、`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。**不要任何定位权限**。
- 唤醒锁：`PARTIAL_WAKE_LOCK`（带超时），停止即释放；预计 1–3 %/小时。
- 一键开始合法性：**桌面小组件点击**与**通知按钮**在官方后台启动 FGS 豁免清单内；**QS 磁贴不在清单** → try/catch，失败则拉起 App 界面再启动。
- 通知 3 渠道（一次定稿，属性不可改）：`monitor_ongoing`（LOW，常驻「剩 N 站」）、`station_alert`（HIGH + 震动）、`station_alert_silent`（HIGH 仅震动，App 内切换）。PendingIntent 一律 `FLAG_IMMUTABLE` + 显式 Intent + 唯一 requestCode；按钮接收器动态注册（`RECEIVER_NOT_EXPORTED`）。
- targetSdk 36：强制 edge-to-edge；CSV 存 `getExternalFilesDir("logs")`（免存储权限，adb pull 可取）。
- 红米 / HyperOS 保活五步（App 内向导，跳转 best-effort，失败回退应用详情页）：① 通知权限与渠道；② 省电策略「无限制」；③ 自启动；④ 后台弹出界面 / 锁屏通知；⑤ 最近任务加锁。beta 系统路径可能不同——异常时走应急降级分支（先「App 可见时监测」验证传感器链路）。

## 七、数据格式

### 7.1 `app/src/main/assets/subway_lines.json`

`schemaVersion` + `lines[{id, name, directions[{id, name, stations[{id, name}]}]}]`；方向**显式写两遍**（便于人工核对）；先放 2 条虚构示例线路，S5 替换真实线路数据。

### 7.2 CSV 三件套（`Android/data/com.metrostop.reminder/files/logs/`）

- `sensor_*.csv`：`t_ms,utc_ms,ax,ay,az,lx,ly,lz,gx,gy,gz,vib,h,state,n`（50 Hz，约 15 MB/小时）；
- `events_*.csv`：`t_ms,type,station_index,station_name,dwell_s,interval_s,note`（type 含 `STATION_ARRIVED` / `ALERT_PREV` / `ALERT_ARRIVED` / `STOP_SUSPECT` / `DATA_GAP` / `CORRECTION_UP` / `MONITOR_END` 等）；
- `*_meta.json`：机型 / 系统版本 / 线路 / 上车站 / 目的站 / 参数快照 / 电量 / 起止时间。

### 7.3 本地设置（DataStore Preferences）

`last_route_line_id`、`last_route_direction_id`、`last_route_boarding_station_id`、`last_route_destination_station_id`、`alert_mode`、`record_csv`、`keepalive_guide_done`、`first_run_done`、`tuning_overrides_json`。

## 十、验证（端到端）

1. `gradlew.bat test`（纯 JVM）：特征数值、状态机合成信号、边界用例、**CSV 回放回归**——每次改阈值必跑；
2. `gradlew.bat assembleDebug` → `adb install -r app\build\outputs\apk\debug\app-debug.apk`；
3. 室内验证：点开始 → 摇手机 30 s → 静置 30 s，调试面板 vib/H/state 变化合理；「离线回放」同一 CSV 与现场一致；
4. 通勤实测验收表（每次填一行）：实际站数 vs 识别站数（误差 ≤1 为合格）、D−1 提醒延迟 ≤20 s、是否被系统杀、耗电 ≤3 %/小时；
5. 导出三件套：`adb pull /sdcard/Android/data/com.metrostop.reminder/files/logs` → 回放调参 → 新阈值写回 `TuningConfig.kt` → **留 replay 回归用例** → 复测真机。

## 十二、风险与对策

| 风险 | 对策 |
|---|---|
| 误检（中途停车 / 曲线减速） | 三条件联合判定 + 60 s 最小间隔 + 手动纠错 + 事件 CSV 供离线分析 |
