## 一、背景与动机（为什么纯 IMU 触顶）

| 证据 | 数字 |
|---|---|
| v3 现场验收（晨高峰站姿 12 站） | 5 站干净自动、5 站静默漏检、3 次信号停车误计，按键 9 次（验收线 ≤1 次） |
| 状态显示错乱 | 真实停稳时刻 7/12 显示「巡航中」；「已停稳」显示而实际运行的样本占 21.5%（13 簇最长 70 s） |
| 晨高峰噪声量级 | 停站窗 vib p90 0.16~0.49（玉双路 1.41）vs 晚通勤 0.05~0.14——vib 时间结构判据在分布重叠区不可分 |
| 蜂窝分区（H3） | 39 个 pci:ci、12/12 站区覆盖、站区小区驻留 30~110 s、各站互不重复、进区早于停稳 0~58 s |
| 高德旁证 | 站级跳变且早于语音报站——与小区进区先行完全一致，证明该信号在成都地铁隧道可做站级定位 |

**分工原则**：让蜂窝回答「车在哪个站区」（身份/位置），让 IMU 回答「停稳了吗」（时刻）——各自只做自己实测擅长的事。

## 二、总体方案

### 2.1 站区映射资产（学习期产出）

- `assets/cell_zones.json`（与 `subway_lines.json` 同级、同重生成模式）：**线路+方向 → 有序站区表**，
  每站 `{station_id, cells: [pci:ci…], confidence, learned_at}`；
- 由离线脚本（`assets/gen_cell_zones.py`，模式同 `real-line-data/gen_lines.py`）从学习期 lab 数据 +
  MARK 真值对齐生成；**入库内容只有 pci:ci 与公开站序，无 GPS / 无个人轨迹**（pci:ci 为运营商网络标识）；
- **站区 cell 提取规则（2026-09-29 补，评审 P3）**：站区 cell = 停稳 MARK 窗 **[−15 s, +40 s]（驻留窗）**
  内驻留 ≥15 s 的 pci:ci；**进站段小区（提前 0~58 s 进区的那部分）不进映射**——否则金融城东 `898`（出现在
  两个进站段）/ `919` / `761` 这类中间段小区会被误吸进站区，进区判定漂移到区间中段；
- 跨趟合并：同一站区在不同学习趟出现的 cell 取**出现率 ≥50%** 者入表，其余标低置信不参与判定；
  **2026-10-07 补**：跨趟站台扇区漂移实测普遍（cd6_to_lanjiagou 两趟 pci:ci 交集仅 7/12，交集合并会
  清空 5 个站区），gen 脚本增补 `--union` **并集合并**模式——上线前须做 0 串站碰撞审计
  （仓库外 `analysis/cross_trip_audit.py` C 段；首次应用 = cd6_to_lanjiagou rideCount=2，见变更记录）；
- 学习期：正常通勤 **每方向 ≥2 趟**（6 号线双向 + 4 号线双向各自独立计），App 双轨——v3 照常计数提醒
  （兜底），lab `cellid` 流 + 「列车进站停稳」MARK 照旧采集；离线对齐产出映射后装机切换。

### 2.2 判定逻辑（core，纯 Kotlin）

- 新增 `CellZoneTracker`：输入 pci:ci 主服务小区序列（1 Hz 节流 + 变化即写，复用 `LabCellCollector` 提升的通用实现），
  输出 zone 状态机：`无分区 / 区间 / 站区(<station>)`；
- **进区**（主服务或邻区列表命中目标站 cell 集，且驻留确认 ≥2 拍）→「进站中」；
  **D−1 提醒触发点（评审 P4 定稿）＝ 进入目的站的前一站站区、驻留确认通过时**（比 v3 的停稳计数
  提前 0~58 s）；进入目的站站区本身 → 状态「即将到站」，不另发提醒（到站提醒仍由区内 IMU 静稳
  计数触发，避免 D−1 退化成到站前 ~30 s 的重复提醒）；
- **计数**：站区内 + IMU 静稳确认（复用 `stillConfirm` / 步态门）→ 计数 + 到站提醒；
  **每站区进区只计一次**（金石路双停车不再双计）；
  **计数锚定（评审 P6 补）**：预热期 / 等车时所在的**上车站站区不计数**——计数自「离开首发站区后的
  首次进区」开始，防止上车站内等车静立被计为首站；
- **免疫**：非站区小区（如早通勤信号停车产生的 20 s `716` 区）不触发任何计数；3 次信号停车误计在该规则下全部消失；
- **降级**：无映射 / cell 数据缺失（无服务、换卡、映射漂移）→ 自动退回 v3 纯 IMU 通道，行为不劣于现状；
- **状态显示**：外显状态改由 `zone × IMU` 驱动——区间=巡航中、进区=进站中·下一站名、区内静稳=已停稳
  （结构性修复 v3 的 7/12 巡航中错乱与 21.5% 停稳漂移）。

### 2.3 辅助通道：系统步数（本轮并入，用户提议）

- `STEP_COUNTER` 累计值 1 Hz 轮询（`ACTIVITY_RECOGNITION` 权限已有，lab `steps` 流已验证）；
- **实测分离度（2026-09-29 早通勤，按 MARK 窗重算）**：乘车 6 号线 27.3 min 与 4 号线 4.5 min 步增
  **严格 0**；走路段 **71~114 步/分**；站台等车 **0~11 步/分**（等车 2 窗口小有边界效应）；
- 定位为**低权重辅助证据**：步态门（陀螺）的对冲通道 + 「站台还在走动 = 尚未上车」判定；
  **不能单独判定「已上车」**（站台静立与乘车同为 0 步）——与 H3 同理，各信号只做自己擅长的事。

### 2.4 platform

- `MonitorService` 挂小区监听（`PhoneStateListener.LISTEN_CELL_INFO`，实现从 `LabCellCollector` 提升为通用类）；
- `READ_PHONE_STATE` 进主链路使用（硬性规则 3 例外扩围：仅蜂窝标识，**定位仍禁**；方案 A 批准即含此项）；
- **`ACCESS_FINE_LOCATION` 同为主链路必需权限（2026-09-30 批次 A1 定稿）**：Android 10+ 读
  `CellInfo` 被平台归类为精确定位数据源，无此权限时 `getAllCellInfo()` 返回空、
  `LISTEN_CELL_INFO` 无回调，且 `start()` 仍返回 true → **静默失效不触发 v3 降级**。
  该权限仅用于通过平台校验读取小区标识，不定位不读坐标（AGENTS.md 规则 3 已同步改写，
  manifest 注释已同步归属；Android 12 起 `requestCellInfoUpdate` 同样要求此权限）；
  节后装机批次（C1）需配套：无样本活性检测 + 运行时授权请求路径（当前挂在 lab 启动链路）；
- 记录：监测会话 CSV 增加 `cell` 列或独立流（回放 = 现场行为的前提，离线分析需要）。

## 三、验收标准

1. **学习期完成**：映射覆盖乘坐线路全部站区（6 号线双向 + 4 号线双向，按「线路+方向」分别学习，
   **每方向 ≥2 趟**）；
2. **回放验收（评审 P2 补：自洽 + 跨趟泛化两级）**：
   - **自洽级**：学习趟 CSV 在「由该趟学出的映射」下回放——12/12 计数、**0 次信号停车误计**、状态显示
     与 MARK 对齐率 ≥90%（映射与数据同源，仅验证实现正确性）；
   - **跨趟泛化级（切主通道门槛）**：用 A 趟学出的映射回放 B 趟（同方向不同日期）CSV，计数与提醒
     全对——两趟互验通过且**该方向 ≥2 趟学习样本**后，该方向才切主通道；晚通勤 CSV 在降级路径下
     不劣化（v3 基线 12/12 保持）；
3. **现场通勤验收**：全程 ≤1 次纠错、D−1 与到站提醒正确、状态显示错乱簇占时 <2%；
4. **降级演练**：移除映射回放 = v3 基线行为（不劣化）；
5. `gradlew test` 全绿且基线不回退；红线自检照旧（新红线待实施时约定）。

## 十、后续方向：小区信号强度（rssi）挖掘（2026-09-30 凌晨记录，未立项）

> 来源：用户提问「手机知不知道每个小区的距离/信号强弱，能不能在强弱上做文章」。经数据验证与现场初挖，立此存档防遗忘。**不挤占主线**（主通道实测 / 泛化回放优先），走调参闭环，未验证前不进判定路径。

**数据条件（已核实，无需新增采集）**：
- rssi 自 2026-09-29 起全程落盘：lab `cellid` 流与主链路 `cell_<stamp>.csv` 每行每小区均含 dbm（格式 `pci:ci:rssi`）；仓库 4 件回放资产同格式。09-28 及更早无小区流（采集器 09-29 凌晨上线）。
- 已有样本：09-29 早 + 晚两趟完整 rssi（cd4 段停稳窗 3 个：市二医院×2 + 太升南路×1，玉双路换乘未标可由事件时刻定位）；此后每趟通勤自动积累。

**现场初挖（2026-09-29 早通勤，cd4_to_wansheng，701:38658715650 共享区）**：

> ⚠️ **2026-10-01 样本污染更正（复核意见 §3.7）**：本段「太升南路停稳窗 -84」实际取的是 701 驻留段（市二医院站台/区间）——09-29 早 v3 在 701 区间段误计太升南路（SR 早于真停稳 78.7s），该时刻被当停稳窗落表。**中位差 4 dB 结论作废**；「701 共享区」本身系映射落表错误的假共享（太升南路真值 = 918/884，已修正入表），用途 1（共享区拆分）随之取消。

- 市二医院停稳窗（±20 s）：rssi 中位 **-80**（-87~-76，7 样本）；太升南路停稳窗：中位 **-84**（-86~-82，8 样本）——中位差 4 dB，方向可分；
- 两站之间区间段走势 -71~-90 大幅跳动（多径/车体/遮挡），单趟不足以下结论；
- 复核脚本式样：监控 STATION_ARRIVED 时刻 ±20 s 窗，取主服务小区（ids[0]）rssi 分布对比。

**潜在用途（按性价比排序）**：
1. **共享区拆虚拟锚点**：若 701 区两站停稳窗 rssi 多趟稳定可分，给共享区补上逐站区分——4 号线段补全三级提醒（当前 D−1 进区即发 + 无「即将到站」）；
2. **进区提前量收紧**：进区加强度阈值（如 ≥某 dbm 才算接近站台），收拢 D−1 触发点缓解文案错位；代价是牺牲提前量，收益存疑；
3. **沿线行进进度**（兴趣向，暂不碰）：漏缆沿线衰减近似线性，理论上可做区间进度。

**2026-09-30 晚目标更正（批次 A7；依据 `设想评审-2026-09-30.md` ② 与 `多趟通勤数据分析-2026-09-30.md` 发现 7/8，复现脚本与数据在案）**：
- **「rssi 判停动」明确否定**：现场采样仅 ~0.2 Hz（中位 5 s，晚通勤 12.7~18.1 s），停稳期自身摆幅中位 13 dB（最大 22 dB）≫ 站间判决差，快衰落零点速率 v/(λ/2) ≈ 200~289 个/s 物理上不可采样——**判停动仍归 IMU**；本节所有用途均不依赖时间分辨率；
- **用途 1（共享区拆分）降级让位 TA**：跨趟复核中位差 4 dB < 组内跨度 17~47 dB，多趟仍不可分（原「方向可分」单趟结论被推翻）；
- **701「假共享」假说优先于拆分（批次 B4）**：两站跨趟 gNB 不同（9438163 vs 9438162，编号相邻）——「共享」可能是学习趟采样不足的假象，按多趟数据 + gNB 重判若证实可分，4 号线 D−1/到达连锁问题直接消失，无需 rssi 硬拆；
- **新增挖掘目标：站内（室分）vs 隧道（漏缆）的 rssi 分布特征**——两类覆盖的统计差异是结构性的，不依赖时间分辨率。

- **TA 升格（2026-09-30 批次 B5，原「彩蛋」定位变更）**：LTE **TA（计时提前量，约 78 m/格）是距离代理，优先级高于 rssi**——`CellSignalStrengthLte.getTimingAdvance()` 在已解析的 `CellInfoLte` 上，无需新权限，行格式扩 `pci:ci:rssi:ta` 不破坏既有解析；预期管理：漏缆 DAS 下单调性非理论必然、设备可能恒返回未知值，先采一行数据再谈标定。

**下一步**：节中离线工作按更正后顺序——B4 701 假共享按 gNB 跨趟重判 → B5 TA+rssi 同批采集（lab 改造）→ B2 rssi 分布特征挖掘 → 有稳定信号再立项（走第三节方案 / 调参闭环）。
