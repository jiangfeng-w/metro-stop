# 蜂窝小区与 Wi-Fi 指纹辅助验证（到站检测的新信号源评估）

> 跨期背景见 [`../../需求与方案.md`](../../需求与方案.md)；本文件只写本需求。
> 背景约束变化（2026-09-28 用户决定）：**个人自用，权限全开，效果优先**——「主链路零权限」不再作为设计约束，任何信号源只要实测有效即可进主链路。硬性规则 3 的「不用定位」语义同步放宽为「不用 GNSS 实时定位」（隧道内已实证无效），蜂窝/Wi-Fi 不在禁止之列。

## 一、背景与动机

1. **用户实测观察（2026-09-28 晚通勤）**：每次列车到站时，Wi-Fi 列表出现一个或多个 `DIRECT-NG...`（Wi-Fi Direct P2P 虚拟接口信标）——用户截图 3 张（18:33 / 18:36 / 18:43，最后一屏含 6 个 DIRECT- 热点），时间上与到站相关；
2. **传感器路线的已知局限**：v2 在站姿下失效（见 [`../multi-signal-detector-v3/需求.md`](../multi-signal-detector-v3/需求.md) §1.1），纯 vib/gyro 的时间结构判据有天花板；隧道内 GNSS 已实证全灭（lab 裁决）；
3. **文献**：气压计是学术热点（站级定位可达），但 K80 无气压计硬件，排除；蜂窝 Cell ID 做地铁定位文献很少（稳定性公认差），但作为**粗区间分段**未见否定证据——值不值得用，只有实测知道。

## 二、核心假设（本需求验证的对象）

| # | 假设 | 验证方法 | 通过标准 |
|---|---|---|---|
| H1 | **每站的 Wi-Fi AP 指纹（BSSID 集合）在分钟级尺度稳定且站间可分** | 下一趟通勤全程 1 Hz 节流记录 BSSID 集合，按 MARK 真值对齐后计算相邻站指纹距离（Jaccard）与同站重复度 | 相邻站指纹距离显著大于同站波动（如 Jaccard 相似度：同站 >0.6、邻站 <0.4，具体阈值分析时定） |
| H2 | **`DIRECT-` 信标的出现/密度与「列车停稳」相关** | 到站时刻前后 ±60 s 的 DIRECT- 计数曲线 vs 区间中段对比 | 到站窗内计数显著高于区间（可做简单的相关性与显著性检验） |
| H3 | **蜂窝小区切换序列可区分「跨站」与「区间内乒乓」** | `getAllCellInfo` 全量记录 CI/PCI，对照真实到站时刻 | 跨站对应的小区切换可由「新 CI 驻留时长 ≥ 某阈值」或「RSSI 跳变」从乒乓切换中分离（≥90% 的真实跨站被唯一一段切换覆盖） |
| H4 | Wi-Fi 扫描限频（后台 2 min/4 次，前台 30 s）在**前台服务 + 1~30 s 间隔**下足够生成站级指纹 | 实测扫描成功率与实际间隔 | 每个站间区间内 ≥3 次成功扫描（不达标则评估 `setScanAlwaysAvailable` / 采集期前台保活的效果） |

## 三、采集方案（lab 旁路新增两流，不动 v2 冻结路径）

### 3.1 新增流

| 流 | 文件 | 内容 | 频率 |
|---|---|---|---|
| `wifi` | `lab_wifi.csv` | `t_ms,utc_ms,ap_count,direct_count,bssid_hash_list`（BSSID 用 SHA-1 截断哈希，不落原 MAC；`direct_count` = SSID 以 `DIRECT-` 开头的个数） | 1 Hz 节流的**扫描结果快照**（每次系统扫描回调触发，缺失秒不补行） |
| `cellid` | `lab_cellid.csv` | `t_ms,utc_ms,cells`（cells = `pci:ci:rssi` 多值用 `\|` 分隔，主服务小区排首） | 1 Hz 节流 + **变化即写**（小区切换不落节流窗） |

### 3.2 权限与 API

- Wi-Fi：`WifiManager.getScanResults()`（需 `NEARBY_WIFI_DEVICES`，API 33+；HyperOS 限频实测见 H4）；
- 蜂窝：`TelephonyManager.getAllCellInfo()` + `PhoneStateListener.LISTEN_CELL_INFO`（`READ_PHONE_STATE` 已在 lab 权限清单内）；
- 注册 `BroadcastReceiver` 监听 `WIFI_SCAN_AVAILABLE` / 主动 `startScan()`（受系统节流，失败次数也记录——限频证据本身是 H4 的数据）。

### 3.3 隐私约束（本仓库 PUBLIC，硬要求）

- **BSSID 一律哈希后落盘**（原 MAC 不入库）；SSID 只保留「是否 DIRECT- 前缀」布尔 + 哈希；
- CI/PCI 是运营商网络标识，可直接落盘；
- 分析资产与早/晚通勤数据一样**只在仓库外**，回归资产只允许进传感器通道数据。

## 四、真值与对齐

- 真值来源（同晚通勤方法）：用户 MARK 时间轴（到站/上车/乘车标记）+ 监测事件 + 手动纠错记录；
- 对齐方式：lab `t_ms` 单调时钟同域，直接对齐；
- 分析脚本进仓库外分析目录（模式同 `2026-09-28-evening-commute`），产出：站间指纹可分性矩阵、DIRECT- 计数与到站的相关图、小区切换-到站对齐表。

## 五、验收标准

1. **工程**：两流采集可用（下一趟通勤数据行数非零、限频行为有记录）；lab 保留策略/目录规范不变；`gradlew test` 全绿（新增 LabFiles 流清单回归更新）；
2. **分析**：H1~H4 逐条给出「成立 / 部分成立 / 不成立」结论 + 数据图；全程结果写回本需求文档并更新速览表；
3. **裁决输出**（三选一，写明理由）：
   - **A. 值得主通道化** → 立项 v4「指纹到站检测」（到站 = 指纹切换，传感器降兜底）；
   - **B. 值得做辅助票** → 并入 v3 的证据门做第四通道；
   - **C. 数据不支持** → 本需求关闭，结论留档。

## 六、不在本范围

- 不改 v2/v3 检测器与任何主链路代码；
- 不建 Wi-Fi 指纹库 / 不做实时匹配（验证先行）；
- 不做蓝牙 beacon（地铁无部署，乘客耳机信标噪声大，除非数据意外支持）。
