# 步态识别与首站判定修正

> 跨期背景（分层 / 状态机 / 数据格式）见 [`../../需求与方案.md`](../../需求与方案.md)；本文件只写本需求。

## 一、要解决的问题

M1 判断「第一次停稳是不是上车站本身」只看**振动幅度**：预热期（`startGraceSec` = 20 s）内 `vib > vibRunTh`(0.25) 持续 `startMovingConfirmSec`(1 s) 即认定「开始时列车已在行驶」（`StationStopDetector.startedInMotion`，`StationStopDetector.kt:143-152`），首站据此决定是否忽略（`MonitorSession.kt:147-160`）。

**但人走路时 vib 同样会超阈值**（实测占比见第四节）→ 用户在站厅 / 站台**边走边点开始**时会被误判为「车上中途开始」→ 列车进站停稳（= 上车站本身）被当成第 1 站计数 → **多算 1 站**；`k == 1` 的短途甚至直接误报「已到达目的站」。

这是总纲第九节「地铁实测 ≥5 站、误差 ≤1」验收的**单点最大风险**：误判一次即用掉整个误差预算；且误判方向是「提前提醒」，比漏检更危险（用户会提前下车）。

**不能回退的反向问题**（M1 已修，本需求必须保持）：真正的「车上中途开始」必须首站计数，否则 `k == 1` 要「摇两次」才提醒（用户 2026-09-25 实测反馈）。

## 二、目标

1. 用**步态特征**区分「人在走」与「车在跑」，不再单看振动幅度；
2. 首站判定改为「**首次停稳前是否观察到列车运行证据**」，自动覆盖全部开始姿势（站台静止 / 站台走路 / 车厢内静止 / 车厢内走动 / 车上中途开始），**不需要**用户选姿势；
3. **不新增权限**：只用已采集的线性加速度 + 陀螺仪（`TYPE_GYROSCOPE`，M1 已在采集并随 CSV 落盘）。不使用 `ACTIVITY_RECOGNITION` / `TYPE_STEP_DETECTOR`（要权限，违背总纲「不申请定位 / 活动权限」的极简取向）；
4. 阈值仍**只能**定义在 `core/model/TuningConfig.kt`（硬性规则 2），并按调参闭环留下 replay 回归用例。

## 三、方案

### 3.1 步态特征（core，纯 Kotlin）

新增 `core/feature/GaitAnalyzer.kt`：输入 vib 序列（滑动窗 `gaitWindowSec` = 1.5 s，@50 Hz 约 75 样本）与陀螺仪幅值序列，输出：

| 特征 | 定义 | 步行的形态 | 列车运行的形态 |
|---|---|---|---|
| `gaitPeakHz` | vib 序列（去均值）在 `gaitBandLowHz`–`gaitBandHighHz`(0.8–4 Hz) 内的**谱峰频率** | 1.5–2.5 Hz（步频） | 无显著窄带峰（轮轨振动为宽带） |
| `gaitPeriodicity` | 谱峰能量 / 同带总能量（0–1），等价于归一化自相关峰值 | 高（≳0.5） | 低 |
| `gyroMagRms` | 陀螺仪三轴幅值 1 s RMS（rad/s） | 高（手机随腿部摆动） | 低（车体旋转极小） |

判定（初版取「三者同时成立」的保守口径）：

```
isWalking = gaitPeriodicity > gaitPeriodicityTh
         && gaitPeakHz ∈ [gaitBandLowHz, gaitBandHighHz]
         && gyroMagRms > gaitGyroTh
```

连续命中 `gaitConfirmSec`(1.5 s) 才输出 `isWalking = true`（避免单帧抖动）。

**实现约束**：与 `FeatureExtractor` 一样**全因果**（只用当前与历史样本，窗内不做未来插值），保证 CSV 回放 ≡ 现场（硬性规则 1 的前提）。

### 3.2 首站判定改为「运行证据」（取代 `startedInMotion`）

`StationStopDetector` 的变化：

- **删除** `startedInMotion` 与预热期 20 s 窗口的幅度判定（`startMovingConfirmSec` 一并删除）；
- **新增** `runEvidenceForSec`：在 WARMUP / CRUISE / STOPPED 三种状态下，只要 `vib > vibRunTh` **且 `!isWalking`** 就累计；累计 ≥ `runEvidenceSec`（初值 5 s）即置 `hasRun = true`；
- `hasRun` 语义由「已观察到一次『到站 → 离站』」扩展为「**已观察到列车运行证据**」（DEPART 分支仍置位，保持兼容）；
- `MonitorSession.translateArrival` 的首站忽略规则简化为**单一条件** `!hasRun`；
- `WARMUP_DONE` 的 note 改为 `started_at_platform` / `started_walking` / `started_on_train`（后者 = 预热期内已满足运行证据）。

**为什么这样能自动覆盖所有姿势**——「首次停稳前是否有列车运行证据」是唯一真正决定首站语义的量：

| 场景 | 运行证据 | 首站判定 | 结果 |
|---|---|---|---|
| 站台静止等车点开始 → 列车进站停稳 | 无（静止） | 忽略 | ✓ 停的是上车站本身 |
| 站台**边走**点开始 → 列车进站停稳 | 无（步态不算证据） | 忽略 | ✓ **本需求要修的主 bug** |
| 站台走路 → 上车 → 列车启动运行 → 到站 | 上车后无步态 + vib 高 ≥ 5 s → 有 | 计数 | ✓ 第 1 站 |
| 车厢内坐好（车未开）点开始 → 启动 → 到站 | 启动后有 | 计数 | ✓ |
| 车上中途开始（车已开） | 预热期内即有 | 计数 | ✓ 保持 M1 行为，不回退 |
| 车厢内**边走边点开始**（车在跑） | 步态期间不计；坐下后 5 s 内成立 | 计数 | ✓ |
| 站台静止但列车未进站，静止 ≥ 8 s 误触发一次「停稳」 | 无 | 忽略 | ✓ 被首站规则吸收（这是首站规则的原始作用） |

**已知边界（接受）**：若整段行程用户一直在走动（车厢内持续走动且从未站定 5 s），`hasRun` 不会置位 → 停站被忽略 → 漏检。现实中必然出现站定段（坐下 / 扶稳），风险极低；若真实数据出现该形态，再评估「步态不阻断运行证据累计、只降权」的折中。

### 3.3 参数（`TuningConfig` 新增 / 删除）

| 参数 | 初值 | 说明 |
|---|---|---|
| `gaitWindowSec` | 1.5 s | 谱分析窗长（需覆盖 ≥2 个步态周期） |
| `gaitBandLowHz` / `gaitBandHighHz` | 0.8 / 4.0 Hz | 步频搜索带 |
| `gaitPeriodicityTh` | 0.5 | 周期性阈值 |
| `gaitGyroTh` | 0.35 rad/s | 陀螺仪 RMS 阈值（**待实测标定**，见 3.4） |
| `gaitConfirmSec` | 1.5 s | 连续命中才算「在走」 |
| `runEvidenceSec` | 5.0 s | 运行证据累计时长（取代 `startMovingConfirmSec`） |
| ~~`startMovingConfirmSec`~~ | — | **删除** |

### 3.4 数据依据与标定前提（重要）

现有 3 个回归 CSV **全部是「手摇模拟」**（在家晃手机模拟列车），**不是真实乘车**，因此：

- 手摇的陀螺仪统计偏高（三个文件 `gyroMag` 均值 0.89 / 3.58 / 1.84 rad/s、峰值 12.7–19.1 rad/s）→ **不能**用来标定 `gaitGyroTh`；
- 但手摇数据在**语义上等价于「列车运行」**（非步态 + vib 高）→ 现有回归用例的期望结果不变，可作为「不误判为走路」的负样本；
- 标定前需用户补录两段真机数据（各 2–3 分钟，开 `record_csv`）：
  1. **走路段**：站厅 → 站台，手持与放口袋各一段；
  2. **真实乘车段**：启动 → 匀速 → 制动 → 停稳（放口袋），并记录实际站数。

> 采集时机建议：与 M1 的「真实通勤 ≥5 站实测」同批完成，一次出行同时满足两项验收。

### 3.5 需要一并处理的技术债

`SensorCollector.kt:86-92` 现在把陀螺仪样本**缓存最后一次值并附到下一个加速度样本**上（注释写「简化处理：丢弃」）。实测 CSV 的 `gx/gy/gz` 填充率 100%，相位差约一个采样周期（~20 ms）。

**结论：保留当前近似。** 理由：步态窗 1.5 s ≫ 20 ms 相位差，且 1–3 Hz 的步态包络对 20 ms 抖动不敏感；改造为双流时间戳对齐会动到采集热路径（50 Hz），收益不成比例。仅把注释从「丢弃」改为明确说明近似关系与误差量级。

## 四、验收标准

1. **单测**（`gradlew test` 全绿，新增 ≥3 项）：
   - 合成「走路 → 上车 → 列车启动 → 到站」序列：首站忽略、第 2 站计数（**新 replay 用例**）；
   - 走路段不被判为运行证据（`hasRun` 保持 `false`）；
   - 三个既有实测套件（`RealCsvRegressionTest` / `RealJourneyRegressionTest` / `RealInMotionStartRegressionTest`）结果**不回退**，中途开始仍首站计数。
2. **真机**（红米 K80）：
   - 站台**边走**点开始 → 上车 → 到站：识别站数 = 实际站数（重点回归项）；
   - 车上中途开始（`k == 1`）：仍首次停站即提醒（不回退）；
   - 真实通勤 ≥5 站：误差 ≤1（并入 M1 验收）。
3. **标定闭环**（硬性规则 2）：走路段 / 乘车段 CSV → 离线回放 → 参数写回 `TuningConfig` → 留用例。

## 五、不在本范围

- **运行中**（CRUISE / BRAKING / STOPPING）用步态门控停稳判定（「步行检测冻结计数」，总纲第十一节 #6）——本需求只改首站判定，不动到站判定，避免引入新漏检；留待有真实数据后单独立项；
- `TYPE_STEP_DETECTOR` / 活动识别 API（需权限）；
- 自动开始（V2+）。
