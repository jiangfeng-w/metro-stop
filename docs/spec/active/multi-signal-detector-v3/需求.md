# 多信号到站判定 v3（步态门 + 站姿乘车识别 + UI 术语中文化）

> 跨期背景见 [`../../需求与方案.md`](../../需求与方案.md)；本文件只写本需求。
> 数据依据：2026-09-28 早/晚通勤 6 号线（坐姿 / 站姿两姿势全量 lab 采集），分析存档仓库外 `metro-analysis\2026-09-28-evening-commute\`。

## 一、要解决的问题（数据实证）

### 1.1 主问题：v2 的 vib 一维判据在站姿下失效

v2 在早通勤（**坐姿**）回放 12/12 全对，但晚通勤（**站姿握扶手**）现场 12 站只自动计 8 站：前 1000 s 内 **12 组真实停站全部被乘车证据门拦截**（EVIDENCE_BLOCKED），用户手动 +1 纠错 11 次。

量化根因（lab 数据切片）：

| 指标 | 早通勤·坐姿 | 晚通勤·站姿 |
|---|---|---|
| vib∈[0.10,0.35] 带内占比 | 63% | 56%（并不差） |
| **最长连续带内段** | **124 s** | **69 s** |
| 「vib<0.10 连续 ≥8 s」段数 | 少 | **18 个**（乘车主段 1413 s 内） |
| 落下带占比（vib<0.10） | — | **37%** |

站姿的持续手部微动（fidget）把 vib 证据带**碎片化**，且 **37% 的时间 vib 低于停稳阈值——在 vib 一维上「站姿乘车」与「停车」不可分**。这不是阈值问题（调 rideBandMinSec 只会在两头误伤），是**一维信息量不足**。

### 1.2 陀螺仪数据证明多维可分（本需求的核心依据）

同一次通勤按场景切片，gyro 1 s RMS：

| 场景 | p50 | p95 | 备注 |
|---|---|---|---|
| 站厅走路 / 楼梯 | 1.18~1.31 | 2.5+ | 与所有非走路场景清晰分离 |
| 站台静立等车 | 0.20 | 0.78 | 比站姿乘车**更高**（人群挤压/转头） |
| 站姿乘车（握扶手） | **0.11~0.14** | 0.59~0.67 | 1410 s 长段稳定 |
| 坐姿玩手机 | 0.19 | 0.77 | 手部小动作 |

结论：**「人在走」用陀螺可分（步态门成立，FINDINGS 预测被验证）；「站台静立 vs 站姿乘车」单看 gyro 有重叠，但站姿乘车具有「低 gyro + 低 vib 带内 + 超长持续（列车运行不中断）」的时间结构**——三维组合可分，任何一维单独都不可分。

### 1.3 次要问题（本轮一并修）

- **区间信号停车误计**：早通勤回放 3 次（终点恰好相抵但中间站名偏移）；
- **大客流站漏检**：陆肖/中和型开门人群噪声盖过停稳阈值（晚通勤现场 STATION_ARRIVED 里 2 站实际是错位后靠纠错拉回来的）；
- **UI 英文术语**：监测页状态卡与通知副标题直接显示 `WARMUP` / `CRUISE` / `STOPPING` 等枚举名，调试面板 `state / vib / H / n / CSV / LINEAR` 等专业缩写无中文注释（详见第六节术语表）。

## 二、目标

1. **步态门**（`GaitGate`）：gyro 区分「人在走」——防止走路/奔跑被当成乘车证据（修扔垃圾类误报的最后一块，同时保护证据带不被走路段污染）；
2. **站姿乘车识别**：用「低 gyro + vib 带内 + 长持续」的时间结构，把「站姿乘车」纳入乘车证据——修晚通勤 12 组拦截；
3. **多维停站判定**：到站判定从「vib 静稳」升级为「vib 静稳 + 近期乘车证据（多维）」，同时压区间信号停车误计与大客流漏检；
4. **UI 术语中文化**：所有面向用户的界面不再裸显英文枚举/缩写（方案见第六节）；
5. 参数仍唯一来源 `TuningConfig`（硬性规则 2），调参闭环不变。

## 三、非目标

- 不引入 Wi-Fi 扫描进主链路（`DIRECT-xxx` 信标观察待下一轮 lab 数据验证相关性后另行立项）；
- 不做运动识别 API / 步数进主链路（`ACTIVITY_RECOGNITION` 权限与 lab 旁路绑定，主链路继续零权限取向——gyro/加速度已有）；
- 不改 CSV 格式（lab 数据面不动）；不改通知渠道属性。

## 四、方案

### 4.1 GaitGate（core/feature，纯 Kotlin，全因果）

输入：陀螺三轴（`MotionSample` 已有 gx/gy/gz）。输出：`isWalking`（连续判定，带 `gaitConfirmSec` 确认与退出容差）。

- 主判据：1 s 窗 `gyroRms > walkGyroTh`（初值 0.6，介于站台 0.20 与走路 1.2 中点；标定后定稿）；
- 可选二票：0.8–4 Hz 步频周期性（FINDINGS 警告其未经验证——**先用真实数据回放验证，不达标就只上主判据**）；
- 走路时不累计乘车证据带（防污染），且「走路中静立 <8 s」不触发停站尝试。

### 4.2 乘车证据的多维化（核心）

`EvidenceTracker` 从「vib 带内连续段」升级为三通道，任一通道满足即可通过证据门：

| 通道 | 判据 | 覆盖姿势 |
|---|---|---|
| A. vib 带（v2 现状） | vib∈[0.10,0.35] 连续 ≥30 s / 150 s 窗 | 坐姿静放 |
| B. 站姿乘车 | vib 带内占比 ≥50% **且** gyroRms<0.6（非走路）**且** 单段持续 ≥45 s | 站姿握扶手（带内 56%、gyro 0.11、千秒级持续） |
| C. 周期性振动 | （保留扩展位，标定后再定） | — |

通道 B 的关键参数（`rideStandBandPct` / `rideStandGyroTh` / `rideStandMinSec`）全部由早+晚两批真实数据回放标定，初值即上表数字。

### 4.3 停站判定 v3

- 到站 = 「vib 静稳跨度确认（v2 机制保留）」**+** 证据门（三通道任一通过）；
- **区间信号停车压制**：信号停车持续时间显著短于站台停站（早通勤数据可量化），增加 `minStopIntervalSec` 之外的「停站时长先验」——初值待标定；
- **大客流漏检**：开门人群噪声期 vib p90≈0.13，可尝试「静稳容差内带外毛刺计入跨度」（`stillTolSec` 语义微调）——标定后决定是否采纳。

### 4.4 UI 术语中文化

原则：**面向用户的界面零裸英文**；调试面板保留英文缩写但加中文。全部术语集中在 strings.xml（文案唯一出口不变）。具体对照表见第六节。

## 五、验收标准

1. **回放回归**（两批真实数据都过）：
   - 早通勤（坐姿）：12/12、提醒时刻不劣化（v2 基线）；
   - **晚通勤（站姿）：自动计数 ≥11/12（允许 1 次纠错），EVIDENCE_BLOCKED 不再出现于乘车段**；
   - 17:20 扔垃圾负样本仍被拦截；
   - 手摇资产（gate 关闭层）不回退；
2. **新增真实数据回归资产**：晚通勤 leg2 入 `replay/`（仅传感器，无位置）；
3. **真机**：下一趟通勤（任意姿势）误差 ≤1、提醒全部响、零纠错为达标线；
4. **UI**：状态卡/通知/调试面板无裸英文枚举（对照第六节验收）；
5. `gradlew test` 全绿（当前 87 项为基线，不回退）。

## 六、UI 术语中文化对照表（实现时逐项过）

| 位置 | 现状（英文） | 方案 |
|---|---|---|
| 状态卡 / 通知副标题 | `WARMUP` `CRUISE` `BRAKING` `STOPPING` `STOPPED` `INTERRUPTED` 等 `DetectorState` 枚举名 | `DetectorState.cnName` 扩展属性或 strings 表：预热中/巡航中/制动中/停稳确认中/已停稳/信号中断（`IDLE/FINISHED` 不外显） |
| 调试面板 | `state` `vib` `H` `n` `CSV` `LINEAR` `ACCEL(降级)` | 标签改中文或中英并排：状态 / 车振(vib) / 加减速(H) / 已计站(n) / 记录 / 线性加速度 / 加速度计(降级) |
| 调试面板指标 | 采样率已有中文；`Metric` 标签逐个核对 | 全中文 |
| `MonitorUiState.state.name` 直显处 | StatusCard / Notifier setSubText / DebugPanel | 统一走中文名映射，**枚举名只进 CSV（分析用），不上 UI** |
| 事件 note（`still_no_brake` 等） | 仅 CSV/回放面板可见 | **保持英文**（分析字段，非用户界面），回放报告显示时加中文注解 |
