# 换乘路线（多段行程）

> 跨期背景见 [`../../需求与方案.md`](../../需求与方案.md) §11 后续优化第 2 项（「本次出行路线（含换乘）」）。
> 本需求 2026-09-28 立项于用户通勤实测需求：上班「6 号线 观东 → 玉双路」换「4 号线 玉双路 → 太升南路」，下班反向。
> **开工前提**：通勤实测数据回传、算法路径红线解除（换乘要动计数与提醒语义）。当前状态 `planned`，只落设计草案。

## 一、要解决的问题

1. 用户上下班各需**换乘一次**。当前 App 只支持单线「上车站 → 目的站」，换乘需在换乘站**手动结束再重新开始**监测，操作繁琐且容易漏（换乘通道里容易错过重新开始）；
2. 单段模式下的提醒语义在换乘场景不成立：第一段到站（换乘站）后不应该是「终点到达」，而是「该换乘了」；第二段需要重新开始计数；
3. 返程要重新选一次方向与四个字段（下班坐反向），体验差。

## 二、目标（草案）

1. 支持**多段路线**：一次选择 A 线 →（换乘站）→ B 线 → 目的站，形成一次「出行」；
2. **总停站数 = 各段站数之和**（示例：12 + 2 = **14**），进度条与「剩 N 站」按整段出行计算；
3. **换乘站到达提醒**：第一段到换乘站时，提醒文案是「换乘 4 号线」（区别于「已到达目的站」），并自动切换到第二段的计数（无需手动停止/开始）；
4. **一键反向**（下班场景）：把出行路线整体倒序（含各段方向），不必重选；
5. 换乘通道内**走路不误计数**（依赖 `gait-discrimination` 的步态判据，本需求不重复实现）。

## 三、非目标

1. 不做「全网最短路径自动规划」（那是导航；本需求是用户显式指定换乘站）；
2. 不做多候选路线 / 备选方案；
3. 不做中途改线 / 动态重规划。

## 四、待决策（开工前须确认）

| # | 问题 | 备选 | 备注 |
|---|---|---|---|
| 1 | 换乘段之间的「换乘时刻」如何识别 | ① 第一段到站即自动切段；② 需要用户按「我已上车」确认 | ① 简单但地铁换乘可能要等车 3~8 min，期间走路可能被误计（依赖步态判据）；② 更稳但多一次交互 |
| 2 | 换乘站的站台等待期是否计入总时长 | 计入（真实通勤耗时） | 影响「已运行时间」的含义 |
| 3 | 换乘步行期（通道内）如何防止误计数 | 冻结计数（不递增）直到识别到「列车启动」 | 与 `gait-discrimination` 协同 |
| 4 | 多段路线的数据模型 | 链表 / 数组 of `RouteSpec`（`MultiLegRoute`） | 纯 Kotlin（`core`），便于单测 |
| 5 | 反向（返程）路线的站名与方向如何映射 | 每段 direction 取反 + 上/下车站互换 | 需保证站序正确 |
| 6 | 「我已多过一站」纠错在多段路线下的语义 | 只对当前段生效 | |
| 7 | 换乘站的到达提醒文案 | 「到 X 了，换乘 Y 号线」+ 震动 | 文案在 strings.xml 集中管理 |
| 8 | UI：路线选择是否引入「添加换乘段」按钮 | 是（默认 0 个换乘段 = 现状不变） | 保持向后兼容 |

## 六、验收标准（草案）

1. 两段路线（12 + 2）能正确选择并显示总站数 14；
2. 真机实测：第一段到玉双路时提醒「换乘 4 号线」，第二段到太升南路提醒到达；识别总站数 = 14（误差 ≤1）；
3. 换乘步行期零误计数；
4. 一键反向（下班）后，站序与站数正确（太升南路 → 玉双路 → 观东 = 2 + 12 = 14）；
5. `gradlew test` 全绿，含多段路线转移用例。
