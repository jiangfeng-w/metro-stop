# CSV 记录默认关闭与自动清理

> 跨期数据格式见 [`../../需求与方案.md`](../../需求与方案.md) 第 7.2 节；本文件只写本需求。

## 一、要解决的问题

1. `record_csv` 默认 **开**（`SettingsStore.kt:40`）且**没有任何清理逻辑**（全仓库无删除实现）→ 每次行程约 **12–19 MB**（实测 5.3 KB/s = 18.6 MB/小时，331 s 行程 1.79 MB），通勤每天约 38 MB、每月约 0.5 GB，长期累积会占满外部存储配额且无人察觉；
2. 这批数据的用途是**调参 / 排障**（回放验证算法），日常通勤**没有保留价值**——却按默认在录；
3. 用户看不到「日志占了多少」，无法自查。

## 二、目标

1. 新装默认**不记录**（`record_csv = false`）；**已安装设备保留用户已选值**，不擅自改动；
2. 需要时手动开启（保留现有设置卡片开关），并让「本次是否在录 + 日志占用空间」**可见**；
3. **自动清理**：以「会话」为单位（三件套同删），默认保留 `最近 10 次会话 / 14 天 / 200 MB`，任一超出即从最旧删起；
4. 清理不得删到**正在录制的会话**，不得删 `replay_report.txt`；
5. 零新增依赖（不引入 WorkManager），且不占用服务启动关键路径（`startForeground` 5 秒红线）。

## 三、方案

### 3.1 默认值与文案

| 文件 | 变化 |
|---|---|
| `platform/data/SettingsStore.kt:40` | `K_RECORD_CSV` 的 fallback `true` → `false` |
| `ui/AppViewModel.kt:47` | `_recordCsv` 初值 `true` → `false`（避免首帧闪烁） |
| `ui/SettingsCard.kt:48` | 文案 → 「记录传感器与事件（调试用，约 15 MB/小时，自动保留最近 10 次）」 |

**兼容说明**：DataStore 只存「用户显式选择过的值」，已安装设备里是显式 `true` → 行为保持开启（继续支撑步态标定与通勤实测取数），无需迁移代码。

### 3.2 可见性

- 设置卡片副标题显示当前 logs 目录占用（如「日志：45 个文件 / 1.9 MB」）；
- 打开开关时提示将自动保留最近 N 次。

### 3.3 清理器（core 纯逻辑 + platform IO 分离）

| 文件 | 职责 |
|---|---|
| `core/retention/CsvRetention.kt`（新，纯 Kotlin） | 纯函数 `selectForDeletion(sessions, nowMs, policy, activeStamp): List<File-ish>`：按「最近 N 次 ∧ 最近 D 天 ∧ 总量 ≤ M MB」选出待删文件；**永不选 `activeStamp`**；**永不选 `replay_report.txt`**。可 JVM 单测 |
| `platform/data/LogsCleaner.kt`（新） | 扫 `getExternalFilesDir("logs")`，按 `sensor_<stamp>.csv` 识别会话（`events_<stamp>.csv` / `<stamp>_meta.json` 同组，容错：缺文件也成组），调 `CsvRetention` 后删除 |
| `platform/service/MonitorService.kt` | 在 `beginMonitoring` 的 IO 协程内触发一次（读设置之后、开始录制之前）；失败只记日志、不影响监测 |

**参数位置**：保留策略数值加进 `TuningConfig`（`retentionSessions = 10` / `retentionDays = 14` / `retentionMaxMb = 200`）——它不是算法阈值，但按硬性规则 2 的精神集中存放，避免第二处硬编码。

**手动入口（可选）**：调试面板加「立即清理日志」按钮，复用同一清理器。

### 3.4 与其它需求的关系

- [`../trip-history-db/需求.md`](../trip-history-db/需求.md)：本需求先落地（很小）。DB 建成后，「删 CSV」只删原始数据，**行程摘要仍在**，两者构成「CSV 短期原始数据 + DB 长期摘要」；
- [`../gait-discrimination/需求.md`](../gait-discrimination/需求.md)：标定需要 CSV → 本需求只改默认值，不影响手动开启，无冲突。

## 四、验收标准

1. **全新安装**（清应用数据）→ 设置卡片开关为**关**；开始监测 → `logs` 目录**不产生**新文件；
2. 手动打开 → 一次行程 → 三件套齐全（`sensor_*` / `events_*` / `*_meta.json`）；
3. 造 15 次会话（复制文件模拟）→ 触发一次清理后仅剩 10 次，且**三件套同删**、`replay_report.txt` 保留、当前会话不受影响；
4. 单测 `CsvRetentionTest`（纯逻辑）覆盖：超次数 / 超天数 / 超体积 / 当前会话保护 / 空目录 / 只有部分文件成组；
5. `gradlew test` 全绿（既有 34 项不回退）；本需求**不触碰** `core/fsm`、`core/feature` 算法路径。

## 五、不在本范围

- 上传 / 云同步 / 分享（M3 的 FileProvider 另立）；
- 行程级统计与历史列表（→ `trip-history-db`）；
- 让用户自定义保留条数（先固定策略，避免 UI 复杂化）。
